# Handover: jev-agent-kit v0.2.0 (2026-10-10)

For the next Claude Code session. Read `CLAUDE.md` (rules), this file (state), `docs/compatibility.md` (what is verified), `docs/sources.md` (what we may reuse). The v0.1 research background is in `docs/REPO_HANDOVER.md`.

## What exists

Public repo `cloud-f1/jev-agent-kit` (MIT). Claude Code plugin that shortens long Bash output before the model sees it.

- **Native Mod** `hooks/register.ts` (TypeScript, loaded directly, no build) + pure core `core/*.ts`.
- **Classic hook** `jev.py hook` (Python stdlib) for Claude Code older than 2.1.287; silenced per session by the `mod-active/<hash>` marker the Mod writes at `session.start`.
- `/jev status | doctor | readback <id>` commands; skills `skills/operate` (shipped) and `.claude/skills/release` (project only).
- Local release gate `scripts/release_check.py`; shared golden fixtures `tests/fixtures/golden.{json,ts}` generated by `scripts/gen_golden.py` from the Python reference core.
- Plugin settings (`userConfig`) in `/config`; precedence defaults < plugin settings < project file; key in secure storage.
- Tests: 78 Python (`uv run --no-project python -m unittest discover -s tests`, verified on 3.10 to 3.14) + 60 Mod/core (`claude plugin test`). No CI (no quota); the gate is local.

## Verified, and what is NOT

Verified live (Claude Code 2.1.295, `claude -p --model haiku`, scratch project): module loads, marker written, classic hook skipped, 30,000 → 570 chars, model received the pruned text and the readback line, `/jev doctor` and `/jev status` work, state files `0600` / dirs `0700`, project hash equals Python's.

**Not verified:** the interactive `/config` screen and the sensitive-key prompt (only seen through `claude -p`), the live Jev API (no key was ever used; every Jev path is stub-tested), `/jev readback` live, interactive-session UI (status line, hot reload), Windows, installing **v0.2.0** from the marketplace (only v0.1.0 was installed), and above all **any cost or success-rate benefit**. Do not claim savings; the paired agent-task benchmark (`docs/EVALUATION.md`) has not been run and needs a budget decision from the user.

## Decisions the user made

- Repo `cloud-f1/jev-agent-kit`, public. Scope v0.2: harden the Python package + native Mod; model routing deferred.
- **Core ported to TypeScript** (not a bridge to Python) so the Mod has no Python dependency; Python stays the reference implementation for parity.
- Single plugin; Mod and classic hook separated at runtime by the marker.
- Release skill is project-only; GitHub Actions removed.
- Reference repos: user wants to "take the essence" (see `docs/sources.md`; `jev-harness` has no license, ideas only).

## Traps already hit (do not rediscover)

- `defaultEnabled: false` in `plugin.json` ⇒ a `--plugin-dir` load registers no module and no hooks. The gate rejects it.
- An installed copy plus `--plugin-dir` share the name `jev-agent-kit`; disable the installed one in scratch tests.
- `claude plugin test` cannot import `.json`; fixtures are mirrored to `.ts`.
- `$.fs.write` has no file mode; the Mod writes via `sh -c 'umask 077; ...'` with stdin.
- Claude Code caps Bash output near 30,000 chars before hooks run.
- The release gate once silently skipped its secret scan because an edit deleted `return files`; a test now covers it. Secret-shaped fakes are allowed only under `tests/` and `scripts/gen_golden.py`.
- Installed plugins are cached by version: bump version (3 places + CHANGELOG) for anything users must receive.

## Independent audit (done 2026-10-10)

13 findings (1 high: redaction let Bearer/JSON-quoted secrets reach the Jev API). All fixed with regression tests; summary in `CHANGELOG.md`. Residual risks the auditor could not settle: whether `/clear`, resume or hot reload re-fires `session.start` (a session without a marker would run both hooks, costing duplicate work, not safety); `$.http.fetch` may follow redirects (the Authorization header is only ever sent to the fixed endpoint).
